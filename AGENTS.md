# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## Project Overview

hiai-rs provides Rust bindings to Huawei's HiAI (CANN) DDK for inference on Ascend NPUs from OpenHarmony. The project is **experimental** and uses a workspace with two crates:

- **hiai-rs-sys**: Raw FFI bindings (unsafe, internal use only), generated by `bindgen` from the pure-C adapter headers.
- **hiai-rs**: Safe Rust wrapper (`TensorDesc` + `dispatch()`).

## Architecture

The HiAI DDK exposes a C++ API (`hiai::op::*`, the GE graph engine, the model manager). Rust cannot call those classes directly, so this crate ships a **pure-C adapter** (`adapter/`) that wraps the DDK into `extern "C"` `cann_*` functions over opaque `Cann*` handles.

```
hiai-rs (dispatch, TensorDesc, error)
    └─ hiai-rs-sys (bindgen: ddk_cann_* functions + Cann* types)
           └─ adapter/ (C++ shim, compiled by cc, linked to libhiai on OHOS)
```

- **Graph build** (WebNN → CANN IR) is *not* part of this crate; it lives in rustnn.
- The adapter is compiled and `libhiai` is linked **only** when `CARGO_CFG_TARGET_ENV == "ohos"`.
- The adapter is a local pure-C shim (Apache-2.0, SPDX headers). Do not modify it unless adding a new `cann_*` symbol that rustnn's converter needs.

## Build Commands

```bash
# Host: generate bindings only (headers are self-contained, no DDK needed)
cargo build

# OpenHarmony device: full build + link
export CANN_DDK=/path/to/CANN-Kit-next/ddk/
export OHOS_SDK_NATIVE=/path/to/OpenHarmony/sdk/native
make ohos-build

# Code quality
make fmt                     # cargo fmt --all
make fmt-check               # check formatting
make clippy                  # clippy -D warnings
make test                    # cargo test
make check-all               # fmt-check + clippy + test
```

## Environment Variables

- `CANN_DDK`: Huawei CANN-Kit DDK path (required for OpenHarmony builds).
- `OHOS_SDK_NATIVE`: OpenHarmony SDK native toolchain (for `aarch64-unknown-linux-ohos`).

## Testing Strategy

- Host: bindgen smoke test (`cargo build`) + unit tests (error/`TensorDesc`, no dispatch).
- Device: real dispatch tests run in rustnn's `cann_device_test` (not here), which needs the OHOS device + NPU.
